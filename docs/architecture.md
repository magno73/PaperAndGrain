# Architecture

## Flow

`AlbumPicker` selects photos and the book size. `PhotoLibrary` asks PhotoKit for the current version of the images. An explicit import from Finder goes through `LocalImages`. `Workspace` saves every resource locally and creates the document. It starts the analysis, one photo at a time, once the editor is available.

`EditorView` edits the document through SwiftUI bindings. A change to a photo or a text updates the view. The workspace triggers autosave itself: after a short pause it takes a copy of the document, and a serial queue encodes it and writes it atomically. Explicit saves and the package copy of **Save As** keep the order of the queue. The workspace keeps the last saved snapshot and skips the write while the book equals it, so opening and closing a book leaves `manifest.json` byte-identical. Opening a book decodes the manifest off the main thread; only quitting still flushes synchronously. `BookPDF` works on a copy of the document so that every export stays consistent.

## Book package

A `.papergrain` project has a `manifest.json`, an `assets/` folder and, when needed, a `looks/` folder. Fields added after the first release are optional in schema v1.

| Data | Contents |
|---|---|
| Book | ID, title, size in mm, page order, schema version and the optional `writerVersion` of the app that last wrote it |
| Photo | ID, name, capture date, oriented dimensions, local file name, optional place, analysis and caption |
| Page | ID, layout type, photos in placement order, heading and story, text position, optional framing and layer order |
| Analysis | List of Vision labels, stable theme keys and revision |
| Film | Book look, per-photo overrides and reference to the LUT stored in the project |
| Print | Bleed, safe margin, PPI, side of the first page and optional cover |
| Cover | Title, back text, photos, and optional positions and crops kept separately for front and back |

The manifest is replaced atomically. **Save Project** updates the existing package. The first save of a draft and **Save As** copy the package to the chosen destination on the save queue, behind a progress overlay, and adopt it once it is written; edits made during the copy are saved in the new place. After a successful **Save As** from a draft, the draft moves to the Trash. Resources resolve under `assets/`. Changes that add optional data must still decode projects saved without those fields.

The workspace checks the folder identity while saving. When the open package no longer matches it (renamed or moved in Finder), the workspace finds it again by volume and file number and keeps saving there. A package that cannot be found (ejected, deleted or in the Trash) shows a clear message; **Save As** writes the current book to a new place, and **Back to Library** or opening another book asks whether to save elsewhere or close without saving.

A book whose `writerVersion` is newer than the app's opens read-only with a message; **Save As** and imports are disabled for it. A book in a read-only location opens without errors and can be copied elsewhere with **Save As**, which makes the copy editable. Writes that fail because of a read-only volume or a missing permission report the read-only location and stop retrying. `Workspace.writerVersion` is 2: a book is stamped 2 only when it has a map page (`Workspace.writerVersion(for:)`); every other book keeps 1 and stays fully readable by 0.10. A map page is saved with an arrangement 0.10 knows, `textOnly` (layout `text`), and is a map by its `map` field, which 0.10 ignores (`BookPage`'s coding in `MapPage.swift`; `map.layout` `aboveText` marks **Map above text**). 0.10 therefore decodes such a book, sees version 2 and opens it read-only as a newer format, instead of failing on an unknown arrangement. In memory the page's arrangement is `map` or `mapAboveText`; a text page whose arrangement changes drops its `map` field so it never reads back as a map. From 0.11 on, `BookStorage.read` also reads the title and `writerVersion` of a manifest it cannot decode and reports a newer one as newer. The command line stamps books with a map page the same way.

The editor is keyed on the document session, not on the book ID: Save As copies and Finder duplicates share the book ID, and the session changes when another package is opened or the book is closed. The old editor clears its undo actions when it goes away.

Drafts live in `~/Library/Application Support/PaperAndGrain/Drafts`, one folder per book named by UUID. The welcome window lists that folder next to the recently opened packages, so a draft stays reachable even when it drops out of the recents list. **Delete Draft…** asks first and moves the draft to the Trash. At launch the app reopens the last suitable project.

`BookStorage.validate` checks every manifest that is read and throws `BookStorage.ValidationError` with an English message that names the page, photo or field, for example `Page 2 (pages[1]) references unknown photo <UUID> in photoIDs`. Photo `pixelWidth` and `pixelHeight` must be between 1 and 1,000,000. `AppErrors.swift` gathers the errors the app shows to the author in the interface language: book moved, newer format, read-only location, damaged manifest, image unavailable (with the file name) and a partial import that lists the unavailable files.

## Analysis and story matching

`PhotoAnalyzer` uses ImageIO to normalize the orientation and Vision to classify the scene. After a confidence filter it keeps the most relevant labels. It maps those labels to stable themes such as `desert`, `wildlife`, `water` and `people`. Theme translations are for the interface. Matching uses English labels and common synonyms in Italian and English, with positive scores for the words or phrases found. Words read in a photo (OCR) count only from four letters up and outside an Italian and English stop list. A theme describes what the model recognizes and is only a suggestion. The current classification does not establish where a photo was taken or who appears in it.

Photos that come from PhotoKit may come from iCloud. The copy asks for the current version, including edits visible in Photos. The analysis works on the local copy and writes the revision and the results to the document. Revision 2 stores classifications with confidence, detections, OCR, pixel measures and a visual fingerprint. The editor applies updates in small batches and stops the analysis when the book changes. Photos added while an analysis runs are queued and analysed when the run ends.

The photo library also accepts dragged files and files promised by Photos. Each file is checked from its image header and copied to a temporary folder, without reading it whole into memory; the readable images are added to the project library. The tray's **Import Files…** uses the same path. A drop follows the document session, so Save As or a move during a slow import does not discard it: the photos are installed in the current package after any copy in progress. Moving the assets and writing the manifest run on the save queue, in a single manifest write.

The inspector computes suggestions off the interface thread when the heading, story, page photos or available photos change. It uses matches with subjects, OCR and themes and shows the most specific source. It cancels the previous search when any of these inputs changes.

## Geometry and PDF

Book dimensions are in millimeters. The gallery geometry goes through `BookLayoutGeometry` and keeps proportions, order and gaps. The first draft groups photos by capture day.

For a full-bleed photo, `framing` goes from 0 to 1 along the axis that is cut when the photo fills the page. A missing value means 0.5. This field is still read when the newer two-axis crop is missing. A spread uses the same image rectangle for both sides. The PDF draws that rectangle through two clipping windows and leaves out the guides. Core Text keeps the text selectable.

`PageComposition` resolves automatic rows, manual frames, text and rules into typographic points, from the top left. Manual frames of photos and text boxes use coordinates normalized to the trim size. A photo placed by hand does not take a slot in the automatic grid. The first move of a photo out of the grid fixes the other visible frames. Canvas zoom only scales the on-screen size, while the photo crop controls the magnification within the frame and the alignment on both axes, including for the print-resolution calculation. The navigator order matches `Book.pages`, with each panorama shown as a single entry.

With a page template, `PageArrangement` assigns frames in the order of the page's photo IDs. `PageComposition` shares the rectangles with the canvas, thumbnails and PDF. Photos beyond the capacity stay in the page data. Applying a template resets the frames and keeps crops, story and boxes. Moving one frame leaves the others in their slots. The **Insert** menu creates pages with page templates; legacy layouts in older books (`gallery`, `text`, `mixed`, `fullPage`, `fullSpread`) render as before.

Full-bleed templates spread the frames to the edges of the format and leave out rules and folios. The PDF extends into the bleed only the frames that reach the outer edge. Edges between photos stay shared.

The fields `BookPage.arrangement`, `BookPage.photoPlacements`, `BookPage.textBoxes`, `BookPage.layerOrder` and `BookCover.backText` are optional. So are `BookPhoto.caption`, `PhotoPlacement.captionPosition` and `EditorialTypography.caption`; a book without them encodes byte for byte as before. The text box fields `backgroundColor`, `hidesBackground`, `borderColor` and `borderWidth` are optional too.

### Captions

The caption text lives on the photo (`BookPhoto.caption`), so it is the same on every page; where it sits is per page (`PhotoPlacement.captionPosition`: `below`, `above`, `inside`, `hidden`, nil for automatic). Resetting frames (`PhotoPlacement.withoutFrame`) keeps crop and caption position. The book has one caption style, `Book.typography.caption`, over the template's `EditorialStyle.defaultCaptionStyle`. `PageComposition.captions` holds, in the order of `photos`, each printed caption's text frame, the band behind a caption on the photo, the resolved position and whether it fits; `captionBand` is the height automatic slots gave up. `CaptionSetter` (`PhotoCaptions.swift`) applies the rules: a caption is as wide as the visible photo, kept inside the area the safe-margin check uses (`Book.textSafeArea`: `PrintGuides.textSafe`, the safe margin less a print service's binding margin on that side of the page, or the plain safe margin if that leaves no room) and off the gutter of a panorama, and as tall as Core Text needs; it sits half a caption line below or above the frame, or on a band at the bottom of the photo whose text stays inside the safe line (the band moves to the top when a **Text over photo** panel covers the bottom). Automatic means below when the text fits above the safe line, otherwise on the photo; for an automatic slot it means below when the slot lies inside the safe line and on the photo when it bleeds. When any automatic slot has a caption below or above, every automatic slot gives up the same band (the tallest such caption plus the gap, at most 45 % of the shortest slot, or 40 % of the area per row in the proportional gallery, which is laid out again with the band under each row). Manual frames never change. A page with no printed caption is laid out exactly as before. A caption is drawn right after its photo, in the photo's layer: the PDF (`BookPDF.drawCaption`, with the band carried into the bleed where it reaches the trim), thumbnails and **Browse the Book** (`miniCaption`), and the canvas, where the caption is the photo control's `attachment` so it follows a drag. The attachment is drawn under the selection handles and never takes a click, so the photo's drag, resize and double-click always win. The click map has a `.caption(photoID)` region after its photo: a click selects the photo. A double-click types in place (`EditorialObject.caption`): on a caption on the paper through a target layered just under its photo, on a band through the photo's double-click, which finds the band from the point (`CanvasObjectControl.onDoubleClickAt`) and crops elsewhere. Typing a caption leaves the story's z-order alone. `CaptionSetter` exists only for a page with a caption to print, typesets each caption once per composition (one framesetter, each width measured once) and cuts a caption after 12 lines or 600 characters with an ellipsis; a cut caption does not fit. A caption under a frame that straddles the gutter of a panorama takes the wider side; when neither side has room it keeps the whole width and does not fit. The full-bleed seam underlap is off while slots give up a band. The cover shows no captions. The preflight's safe-margin warning (`PrintGuides.keepsInsideSafe`) checks each caption that fits, with the caption as target.

`BookPage.layerOrder` lists the layers from bottom to top as the strings `photo:UUID`, `story` and `box:UUID`. The story, the heading and their background form a single layer. Without the field, photos sit below the story and boxes above it, as in older projects. After a reorder, a new photo goes to the bottom and a new box to the top. `PageComposition.layers` resolves the order once, and the canvas (`zIndex`), thumbnails, click map, the detection of the photo under the pointer and the PDF all share it. IDs no longer on the page are ignored.

`EditorialTextStyle` adds `color` (0xRRGGBB) and `lineSpacing` (a multiple of the line height, from 0.8 to 2). Both inherit from the book like font, size and alignment. `EditorialStyle.typography` applies them as the Core Text color and `lineHeightMultiple`, so the editor and the PDF match. `BookCoverGeometry` resolves the two faces for the editor and for `Cover.pdf`, for a given face size. The back cover can hold text and a photo. The title page is an interior text page inserted at the start of `Book.pages`.

Cropping opens a temporary edit directly on the page. Gestures adjust the photo and the frame. Confirming applies position and crop together in a single undoable step. On-screen edits do not activate the app and keyboard focus stays where the window puts it. File panels are presented as asynchronous sheets attached to the book window, never to Help or Settings. The workspace checks the identity of the book and its folder before it uses the result of a sheet.

Snapping uses the free position at every update of the drag. It looks for edges and centers of the other photos and boxes on the same page within six screen points, regardless of zoom, with one guide per axis. The page itself, or the cover face, is passed as `edges` and pulls harder, by `CanvasAlignment.edgeToleranceFactor` (1.5 times the reach, so nine screen points). With equal positions, the reference that is closest relative to its reach wins. The guides show the chosen references and disappear when snapping ends. A released drag commits exactly the placement shown on screen and holds it until the document updates. The project stores only the final frame position.

### Map pages

`PageArrangement.map` (the whole page: the safe area, or the trim in Essential, Berlin Notebook and Postcard) and `.mapAboveText` (the map above the story) carry `BookPage.map: PageMap` (which photos, route, place names, borders, zoom, offset, and the author's names or hidden places by a position rounded to 0.01°). `PageComposition.map` (`MapComposition`) is built once and read by the canvas, thumbnails, **Browse the Book**, the preflight and the PDF; `MapRenderer.draw` paints it as paths and text under everything else on the page, so the PDF stays vector. The photos are those placed in the book (or all), with a location, in capture order; points closer than 2 % of the map's diagonal are one place. `MapGeometry.region` takes the smallest box around them, pads it by 15 %, gives it at least 3° of longitude and the frame's proportions, and leaves out the largest gap of longitude around the globe, so a trip across 180° takes the narrower window; Mercator stops at 80°. Geography is clipped to the region (Sutherland–Hodgman for land and lakes, Liang–Barsky for borders) and cached by region and frame (`MapShapeCache`). A place is named after its photos' most common place name, else the nearest populated place within 50 km in the interface language, else nothing; labels in the caption style go right, left, above or below the dot, most photos first, and are dropped when none fits. A map with no located photo draws nothing in the PDF and is an Issues blocker (`mapWithoutPlaces`).

`MapDataStore` reads `Resources/MapData/world.mapdata` once: off the main thread in the editor (`prepare()`, after which the canvas and the navigator redraw) and on the exporting thread for the PDF. The file is raw DEFLATE over a small binary format (quantized, delta-encoded coordinates) written by `scripts/make-map-data.py` from Natural Earth (1:50m land, lakes and borders, 1:10m places), pinned to release v5.1.2; see `Resources/MapData/CREDITS.md`. No map service is used (decisions D4, D8).

### Copy and paste

`CanvasClipboard` is the private pasteboard type `me.magno.paperandgrain.objects`: JSON with the source book and page ids, the source page size, and the objects back to front, each with a `kind` (`photo`: id, frame in points, crop, caption position; `textBox`: the whole `PageTextBox` and its frame; `story`: heading, text, typography, the heading, story and backdrop frames as drawn, and its extent). Text boxes and stories also go on the pasteboard as plain text. `paste(into:book:)` is pure: frames keep their points (moved inside a smaller page), text boxes get new ids and move 12 pt on the page they came from, a photo already on the page or from another book is skipped (reported to the canvas notice), the story becomes the page's story when it has none (with manual frames, so it shows on any layout) and a text box otherwise, and the pasted objects go on top in their order (`layerOrder`). Cut is copy then `BookPage.removeObjects` (the story's heading, text and frames go too). Plain text from another app becomes a centered text box. Every command is one `editPages` step and selects what it added.

The standard Edit menu items send `cut:`, `copy:` and `paste:` through the responder chain. `CanvasDeleteShortcut.Anchor` inserts a `CanvasEditResponder` right after the book window (`window.nextResponder`), so a focused text field or text view handles them first and the canvas only when no text is first responder; `validateMenuItem` enables them from the selection and the pasteboard. Other windows are untouched. The responder does nothing while a sheet is attached to the window, and Paste is enabled only when the canvas has the keyboard and the pasteboard holds objects this version can read or plain text. **Edit › Duplicate** is a menu command: ⌘D belongs to it while text boxes or the story are selected on the canvas and no text is typed, and to **Page › Duplicate Page** otherwise (photos alone cannot be duplicated on their page); the shortcut moves between the two items. A photo's whole `PhotoPlacement` travels, its frame moved inside the page when less than half of it would show; a photo deleted from the book since the copy is reported as such. Cutting the story also clears the page's `typography`, which styles only the story.

### Multiple selection

The single selection (`canvasPhotoSelection`, `selectedBox`, `selectedEditorial`) still drives the inspector, the handles and every single-object gesture. `EditorView.canvasGroup` (`CanvasGroupSelection`) holds two or more objects of one page as `PageLayer`s, in the order they were selected; while it is active the single selection is empty, so the Photo and Text tabs and the handles go away, and any single selection (a click, the library, the cover) ends it. `CanvasDeleteShortcut` passes the click's modifiers (⇧ or ⌘ toggles an object), turns ⌘A outside text into `selectAllObjects`, and reports a drag that starts on blank paper (`canBeginMarquee`) as a selection rectangle, which `CanvasGroupSelection.touched` resolves against `EditorView.selectableObjects` (photos, text boxes, and the story as one object when it has text). Members draw an outline (`CanvasObjectControl.outlined`); their drag reports its translation through `groupMove` instead of moving or swapping alone. `dragGroup` clamps the move with `CanvasGroupGeometry.clampedTranslation(members:)`: the intersection of what each member may do, text within the page and a photo within the area a single drag allows (`CanvasPhotoGeometry.movementBounds`), and a member already past its limits can only come back. The release commits the move last shown, snapping included. A pointer-down, a change of selection or page clears the drag and the rectangle, and pages do not turn by scrolling while either is in progress. ⇧/⌘-click on the text being typed goes to the text and snaps the bounding box against the page and the other objects. The drag offset and the selection rectangle live in `CanvasGroupDrag`, an observable object read only by `GroupDragFollower` and `GroupDragOverlay`, so the editor does not redraw on every pointer move. Every action ends in `BookPage.applyFrames`: photos in an automatic slot get a manual frame (in an automatic gallery the other visible frames are fixed first, as for a single drag), text boxes take their frame, the story moves as one group; one `editPages` call, one undo step. Align uses the selection's bounding box, or for one object `PrintGuides.safe` (a photo) or `Book.textSafeArea` (text: `textSafe` with a print service's binding margin, the area captions use too, with the page sides cached per book in `RightPages`); enabling a command reads only the selection, and frames are measured when it runs, the story only when it is selected; distribute keeps the outer two; same size takes the object selected last, photos keeping their proportions. `BookPage.moveLayers` moves the selected layers together and keeps their order. Delete removes the photos and boxes; the story stays, as with a single Delete. Captions follow their photos.

Swapping uses the pointer position on the canvas and starts inside another visible photo on the same page. The command swaps frames and order, keeps the crops tied to the photos and undoes in a single step. In fixed-position templates, automatic frames stay automatic. In proportion-based grids the visible frames are fixed before the swap.

Resizing keeps the opposite corner. Photos keep their proportions, and the crop handles can snap one axis independently of the other. The window monitor forwards the click after the button is released. The selection map uses the frames already computed by the canvas, in drawing order. Shortcuts respect active text fields. A click in the library resolves the thumbnail coordinates and keeps the inspector mode that is open.

The bundled film-emulation LUTs (`Resources/FilmLooks`) are sRGB resources with descriptive names. The catalog separates LUTs meant for linear contrast from those meant for images already developed with a standard slide-film look. When one is chosen, the package receives the CUBE copy with the same naming scheme as imported LUTs. The shared render of the editor and the PDF keeps reading the LUT from the package.

Thumbnails use `PageComposition` to draw each photo with its actual frame and crop. The navigator keeps the pages side by side even in single-page view. Dragging is bound to a single `BookPage`, panoramas that span two physical pages included.

Photo rectangles can be up to four times the page size. The model keeps a reachable part of the photo on the canvas and applies the trim only on screen and in print. Text boxes keep using coordinates inside the page. The box being typed in shares the saved text with the inspector and with Core Text.

The optional frames of heading, story and cover text use normalized coordinates. The editor offers dragging and resizing with corner and side handles. The first change to the frames of a page keeps the position of the other block. Missing fields rebuild the starting positions from the template and the typography. Rendering uses the full width of manual frames. The inner margin of free text boxes is configurable. An empty text box prints only what the author styled: a fill other than the paper, or a border; the navigator thumbnails follow the same rule.

Dragging the story as a group applies the same offset to the heading, the text and any background frames. The overall box keeps the move within the page edges. Background frames are saved as normalized coordinates and keep their position while the single texts are dragged. Thumbnails and PDF use the same frames.

Swiss Grid, Berlin Notebook and Japanese Interval define positions for automatic galleries and panels for **Text over photo**. `PageComposition` resolves frames, heading size and panel position. The editor, thumbnails, template chooser and exporter draw the panel with the palette and the graphic mark of `EditorialStyle`. The size set by the author takes precedence over the automatic heading scaling.

`BookPhoto.adjustments` is optional in existing projects. `PhotoAdjustments` measures a reduced copy of the photo to propose repeatable light and color changes. The shared pipeline applies the adjustments to the photo before the film look and the grain. The PDF, the editor and the thumbnails use the same values. The imported image file stays the reference for comparison. Sharpening and noise-reduction radii are fractions of the long edge, so a preview and the print render get the same effect at the same viewing size.

`PhotoResolution` measures the print resolution of a placed photo: its pixels over the printed size, crop and zoom included. The preflight warnings, the canvas badge and the **Photo** tab share it. Values are compared rounded, so a photo exactly at the target does not warn.

`EditorPreviewLoader` shares identical requests and uses separate caches and queues for thumbnails and canvas previews. While a slider moves, provisional values update only the canvas preview, at intervals. The **Film** preview during a gesture uses its own queue and at most 640 pixels on the long side. On release, the editor registers a single undoable action and loads the high-resolution preview. Thumbnails use the committed values. Cover frames and crops are shared by canvas, thumbnails and PDF. In print, each photo is clipped to its own face and bleed.

The inspector observes its own navigation. Filtered library results can be sorted by day, place, main subject or usage. The place comes from IPTC or GPS fields and from the location in Photos when available. For older projects the inspector reads the metadata of the copies in the background. For copies without a place it can query Photo IDs the user already authorized, without asking for access. Unnamed coordinates are grouped in zones of about 0.05°. The coordinates of library thumbnails are measured inside the inspector and read on click. The swatches of the **Film** panel have a render queue separate from the book and library thumbnails.

The binary with the `cli` argument uses the app's model, import, analysis and rendering without opening the window. Editing commands work on a private copy of the package and publish with an exclusive rename. `inspect` returns the validated manifest with the original indices for JSON Patch. Results and errors are JSON. [CLI contract](cli.md)

### Print output

Before any export, `BookPDF.preflight` checks text overflow, unknown photos, photo files missing on disk and unreadable LUTs for the chosen profile, and returns them as blockers separate from the print warnings (resolution below the target, compensation blanks, a caption that does not fit: on its photo and taller than half of it, across the trim, or taller than the band an automatic layout kept for it). Each `PreflightIssue` carries the printed page number, the page's id, an optional `IssueTarget` (photo, text box, story, caption or cover face) and an `id` built from the problem kind, page id and target, so rows keep their identity between runs. `destination(in:)` resolves an issue to a page or a cover face. `Problem.kind`, `Problem.symbol`, `PreflightIssue.message` and `EditorView.issueFix(for:)` are exhaustive `switch` statements: a new `Problem` case does not compile until each handles it, and a kind gets a fix button by returning an `IssueFix` from `issueFix(for:)`.

`IssueMonitor` keeps the result for the open book: each change restarts a 0.6 s wait, the check runs on a detached task off the main thread, and a run that a newer change overtakes is cancelled and never published. The monitor takes its clock and check as closures so tests can drive it. `IssueList` draws the rows (blockers, then warnings, each grouped by page) for the toolbar popover and for the export sheet. The menu command opens the same popover from an anchor on the canvas, so it works without the toolbar item, and a change of the package location reruns the check. A cancelled run also cancels the detached check, which stops at the next page. The export sheet takes the same `fix` provider as the popover, but the app scene that opens it cannot reach the editor, so it passes none yet. A photo placed twice on a page gets an `occurrence` in its id; an overflow message names its subject (story, first words of the box, cover face). The live list checks `EditorView.issuesProfile`: the book's print-service plan (`.service(PrintPlan)`) when **Book & Print** chose a product that is in the catalog, otherwise `.print`. On the 50-page, 150-photo synthetic book the check takes about 4 ms in a release build.

`BookSpelling` (`SpellChecking.swift`) checks the book's texts for the Issues list. `texts(of:)` lists every typed text with its page, target and cover face (captions once, on the first page of a placed photo). `SystemSpellChecker`, behind the `SpellChecking` protocol so tests use a fake, detects the language of each text with `NLLanguageRecognizer` (no hints: a hint made a German sentence read as English) and passes it to `NSSpellChecker.checkSpelling(of:startingAt:language:…)`, which honours it (a probe checked German text as German; the options-based `check(_:range:types:options:…)` detects the language itself, ignores the one asked for and returns orthography results that covered whole headings, so it is not used). Italian and English are used for a short text (fewer than three words) or an unclear one, where a word counts only if both dictionaries flag it; a text in a language the Mac has no dictionary for is not checked. `NSSpellChecker` has no documented thread safety and AppKit uses the shared instance on the main thread while the author types, so the check runs on the main actor, one text at a time with a `Task.yield()` between texts, after the preflight (`IssueMonitor.Extra`, published together with it so rows do not flicker). Measured on a synthetic 50-page book of 900-character stories: about 220 ms in all, the first (cold) text 7 ms, then about 4.3 ms per text, longest 4.6 ms; later runs only re-check the texts that changed. Answers are kept by text; a cancelled run keeps them all. Place names of the photos, `Book.ignoredSpellings` (optional, absent in 0.10 books), words the system learned, capitals, digits and words under three letters are filtered afterwards, so ignoring or learning a word costs no new check. ’ is read as '; a word after an elided prefix (dell'Etosha gives Etosha) and a hyphenated word whose parts are all known also match. One row per different word of each page and target (a heading and a story are one target); the issue id includes the word. The export sheet does not run the check: it shows blockers and print warnings only, and spelling stays in the editor's Issues list. `checksSpelling()` adds a hidden probe view that switches on continuous spell checking in the control it is the background of: the `NSTextView` of a `TextEditor` when it appears, and the shared field editor of a `TextField` when the field becomes first responder (a key-value observation of the window's first responder), restoring the field editor's previous setting when editing ends. It never touches other fields and leaves autocorrection off. `TextEditingCommands()` adds the system's Spelling and Grammar menu.

A cover board's width may follow the page count: Saal Digital's cover width is not a constant board plus the spine, so its entry gives each size a table of board widths (fold-over included, `hingeWithinPanel`), worked out from the printer's cover width.

`SimilarPhotos` groups near-duplicates from `PhotoVisualSignals.perceptualHash` (a 64-bit difference hash) with `PhotoAnalyzer`'s measure, the share of differing bits: a pair is similar at distance at most **0.125** (8 bits), or at most **0.16** (10 bits) when both photos have capture dates within 120 s of each other. Groups are the connected sets (union-find over all pairs); photos without a hash are never grouped; the result does not depend on input order (members sorted by date then id). The thresholds were tuned on generated pictures (200 random scenes of gradients and shapes, 600 x 400): the same scene brightened by 20 % was within 6 bits in 195 of 200 cases and within 8 bits in all 200; shifted 2 % of the width, 154 / 178 / 190 of 200 within 6 / 8 / 10 bits; cropped 5 % and rescaled, 59 / 106 / 148; shifted 5 %, 22 / 56 / 95. The 19,900 pairs of different scenes were never closer than 11 bits (median 32). The PRD's 0.10 would have missed a third of the 2 % shifts and 70 % of the 5 % crops, so the plain threshold is 8 bits, which leaves 3 bits to the closest different pair, and the time rule stays at 10 bits, which leaves only 1 bit, justified only by the 2-minute proximity. A difference hash of a flat sky or a night scene is less distinctive than these scenes, so these values are meant to be conservative; moving either threshold is one constant. Grouping 1,000 photos takes about 0.3 ms in a release build and 40 ms in a debug build (`SimilarPhotosTests`), run on a detached task whenever a hash or date changes (`EditorView.refreshSimilarGroups`). Stacks are built from the photos that pass the library's filter and search (`SimilarPhotos.stacks(_:visible:…)`): a group keeps its visible members and stacks when two or more remain; the shown photo is the placed one, then the sharpest (`visual.sharpness`), then the earliest, among those. `SimilarStackIndex` hides the other members from the list and lays an opened stack out after its shown photo. The grouping key (`SimilarKeyItem`: id, unparsed hash, date) is cheap to rebuild on each render; hashes are parsed on the detached task, and the tray looks photos up by the editor's id index instead of building a dictionary. Groups are connected sets, so a chain can hold photos that are not alike: **Use This One** replaces only members within the threshold of the chosen photo directly (`SimilarPhotos.replaceable`), through `BookPage.substitutePhoto` on every page in one `editPages` call (frame, crop and layer move to the chosen photo; when the page already has it the other is only removed) plus the cover ids, registered in the same undo group under the same name. The compare sheet shows the pages that will change before the click. Captions belong to the photo, so `SimilarPhotos.captionCarry` decides what the chosen photo keeps: with no caption it takes the first caption among the replaced photos (`registerPhotoValue`, same undo group and name); with its own caption it keeps it, and the sheet says when a replaced photo had a different one.

`PhotoRelink` holds the pure parts of repairing missing photos (which photos have no file, matching files by name ignoring case and extension, the photo's values after a relink). `Workspace.relinkPhotos` and `copyAgainFromPhotos` stage the new files through `DroppedPhotos` (the same header check and copy as every import), then `appendDroppedPhotos(replacing:)` moves them into the package and writes the manifest in one step on the save queue, so a relink survives Save As and a move like an import does. The photo keeps its id, name, date, film and adjustments; filename, pixel size are replaced and `analysis` is cleared, which makes `analyze` run again. Preview caches are keyed by file URL, so the new file name is a new key and nothing needs purging. The editor finds missing files off the main thread (`refreshMissingFiles`) for its menus; `EditorPreview` shows `MissingPhotoPlaceholder` when a render fails and the file is gone. The export sheet cannot offer the fix button: it is a sheet of the app scene, and a file panel cannot open on top of it; the editor's Issues list has it.

`PrintGuides.frames(pageSize:settings:zones:)` is the one place that computes the trim, the safe line (`safeMM` inside) and the bleed line (`bleedMM` outside) of a page in points; its `zones` input is where print-service profiles will add hinge, inner-margin and spine areas. `PrintGuidesOverlay` draws it over the canvas only (never in `mini`, **Browse the Book** or `BookPDF`, so the PDF is unaffected by the toggle, which is an `@AppStorage` flag). The same value feeds two preflight warnings for the profiles that have print settings: `.textOutsideSafeMargin` (the frame of a story or printing text box is not inside the safe line) and `.photoNearEdge` (a photo frame edge is more than 0.25 mm and less than the bleed inside the trim; the binding-side edge of a single page is skipped, a full spread has none). Both are computed from the composition at bleed 0.

The export sheet shows blockers as errors and disables **Continue** while any remain. The progress card shows the share of sheets rendered.

Every profile composes pages and covers at the editor's frame size and computes the crop for that frame. A photo that reaches the trim is carried into the bleed with its real pixels where the crop has spare image, and with a pixel-exact reflection only where it has none, so the picture inside the trim matches the editor. The underlap that hides antialiased seams between full-bleed tiles follows the layer order: a photo extends under each neighbor painted after it. A cover band or rule that reaches the trim continues to the outer edge of its face.

Renders are embedded as JPEG-backed images: quality 0.95 at the book's target resolution for the print profiles, 0.85 at about 150 ppi for the viewing PDF. The PDF is written to a hidden file next to the destination, page by page, and moved into place when complete, so an error never replaces an existing file. The exporter keeps its last developed photo, so both halves of a panorama and a photo repeated on the next page are rendered once.

The print export uses explicit TrimBox and BleedBox and embeds sRGB as the output intent. Books that start on the right and panoramas can need compensation blanks; these are filled with the template's paper color, bleed included. Printed folios and print warnings use `PageComposition.pageNumbers`, the same numbering as the navigator, so blanks never shift page numbers. Print writes the interior and the cover as separate files. Before rendering, it checks the destination folder: a folder that holds only a previous `Interior.pdf`, `Cover.pdf` and `.DS_Store` is replaced, any other content is refused at once. Bleed and spine must be set from the specifications of the chosen product.

### Print-service profiles

A printer's product is a `PrintProfile` (`PrintProfile.swift`), a `Codable` value read from `Resources/PrintProfiles`, one JSON file per service holding one profile or an array. `PrintProfileCatalog.bundled` loads it once: an app bundle reads only its own `Contents/Resources/PrintProfiles`; a run without a bundle (`swift run`, `swift test`) reads the repository's folder. `PrintProfileCatalog.read(_:)` checks every entry (`PrintProfile.problems`: https source, `yyyy-MM-dd` date, unique ids, finite lengths that are not negative, positive trims and boards, edges and sizes that are fixed or from the quote, a flat cover with a spine measure, a spread layout that starts on the left) and skips a file that does not decode, an entry that breaks a rule or a repeated id, recording the file and the reason (`skipped`); one bad file never removes the others, so the `pixart` alias keeps working. Skipped files are logged (subsystem `me.magno.paperandgrain`, category `print-profiles`) and named in **Book & Print**. Decoding errors read as a path and a reason (`interior.bleed: Edges need top, bottom, outer and inner…`, `[0].service: missing` in an array file). `load(from:)` is the strict form the catalog tests use. Adding a printer is adding a file; the tests load five test-only entries from `Tests/Fixtures/PrintProfiles` to prove it.

All lengths are millimetres. A length is a number or `{"mm": …, "source": "9 pt"}`, so an entry keeps the printer's own value and unit. The fields:

| Field | Contents |
|---|---|
| `id`, `service`, `product`, `binding`, `regions` | Identity. `product` is English and Italian; `binding` is `hardcover`, `layflat` or `softcover`. |
| `sourceURL`, `verifiedOn`, `notes` | Provenance, shown next to the product with the not-affiliated notice (decision D5). |
| `papers` | Optional paper choices that spine tables refer to, each with its own `pages` limits. |
| `interior` | `layout` (`single` pages or one `spread` per PDF page), `bleed` and `safe` per edge (`top`, `bottom`, `outer`, `inner` = binding; one value sets all four, otherwise all four are named; a bleed edge can come from the quote), `firstPage` (the side of the first interior page in the PDF), `ends` (`pages`; `insideCovers` when the first and last pages print on the inside of the covers; `endpapers` when they are glued down: the export prints them blank), `targetPPI`, and `pages` (`minimum`, `maximum`, `multiple`, `coverPagesCounted`). |
| `cover` | `kind`: `none`, `interiorPages` (front first and back last in the interior PDF, at trim size) or `flat` (back, spine, front). For a flat cover: `panel` (the board when it differs from the page, fixed or from the quote), `hinge`, `spine` and `wrap` as measures, `hingeWithinPanel` (Saal's fold-over: the hinge lies inside the board width, so the cover keeps its outer width and the face narrows), `bleed` beyond the wrap per edge (fixed or from the quote), `safe`. |
| `files` | `single` (one PDF; a flat cover is its first page) or `separate` (a folder with `interior` and `cover` file names). |
| `color` | `accepts` (`srgb`, `cmyk`), the named `iccProfile`, the PDF `standard` the printer asks for, `flattenTransparency`. The app does not certify a standard (decision D6) and still writes sRGB; T12 reads these fields. |
| `sizes` | Each with `id`, an optional `name`, the trim (fixed, or from the quote when the printer gives the exact page per order: any book size in the range is this size, and `typicalMM` is the one menus propose), and `pages` and `cover` fields that replace the product's where the size differs. Page limits apply paper over size over product. |

A measure is a fixed length, `{"quote": {"minMM", "maxMM", "minExclusive", "typicalMM"}}` (typed by the author from the printer's quote; the range is inclusive unless `minExclusive`), `{"formula": {"baseMM", "mmPerPage"}}` or `{"table": {"rows": [{"paper", "upToPages", "mm"}]}}` (the first row whose `upToPages` reaches the interior page count). The measures the author can type (`PrintMeasure`: spine, hinge, wrap, board width and height, cover bleed, interior bleed) live in `PrintSettings.profileMeasures`; **Book & Print › Print service** edits them, and values changed in the export sheet for the book's own product are saved there as one undo step (**Print Service Measures**), so the live Issues list clears its blocker. The author's value always wins; a spine from a quote falls back to `BookCover.spineMM`. A measure past the end of its table is reported with the table's last page count.

`PrintSettings.profileID`, `profileSizeID`, `profilePaperID` and `profileMeasures` are optional, so 0.10 books are unchanged and keep exporting through Generic Print. `PrintSettings.choose(_:size:paperID:)` records a product and takes its bleed (the largest edge) and safe margin (the largest outer edge, because the layout keeps one margin on every side; the binding margin is shown with the rules). It never changes the format: **Book & Print** offers the product's sizes and changes the size only on the author's click, and keeps `profileSizeID` in step when the book's size changes to another size of the product.

`PrintPlan` (`PrintProfileCatalog.swift`) is a product resolved for a book: the size (the chosen one if the book has its trim, else any size with the book's trim, so a stale choice is not an error), the paper and the measures. It gives the interior settings the export uses (the book's own with the product's largest bleed, layout and resolution), the imposition (`BookPDF.Imposition`), the page count the printer counts (`interiorPages + coverPagesCounted`), each measure, the product's issues (`sizeNotOffered` and `missingMeasure` block the export; `pageCount` below the minimum or above the maximum is a warning that gives both the printer's count and the book's own pages), `zones(for:interiorPages:)`, and `guideZones(pageSize:onRight:spread:safeMM:)`, the binding strip of a product whose inner margin is wider than the book's safe margin, as a `PrintGuides.Zone` of kind `innerMargin`. The canvas passes those zones to `PrintGuides.frames`, with the side of each page from `BookPDF.rightPageIDs`; `PrintGuides.textSafe` is the safe area less the zones, the overlay draws its outline as the dashed line and tints the zone, and `PrintGuides.keepsInsideSafe` checks against it. That one function serves headings, stories, text boxes and, after their rebase, captions; the preflight builds the same guides for each page, so a text box 7 mm from the binding is flagged for Pixartprinting (15 mm) and for a 45 pt binding margin.

`BookPDF.write(_:directory:plan:to:)` is the one path for every product. It imposes the interior like Generic Print and, when `firstPage` is `right`, shifts it by one slot (a book whose page 1 is on the left gets a leading blank; one whose page 1 is on the right loses Generic Print's). Glued endpapers become a blank first and last page (two blanks at the start when page 1 must keep its side). Trailing blanks then bring the count the printer takes, cover pages included, to the product's `multiple`, so an odd book is padded instead of refused. Each PDF page gets its own media and trim boxes from the bleed per edge: the binding edge of a right page is its left side. The page is drawn with the largest bleed and clipped to its own edges, so `draw(_:pageNumber:…)` is unchanged. A flat cover lays both faces out on the board (`BookCoverGeometry(book:front:size:)`), so the title is fitted in the width it is drawn in; its trim box is boards, hinges and spine, and its media adds the wrap and the bleed. A cover overflow is reported as the cover. The exporter keeps sRGB rendering and selectable type.

The Pixartprinting 21 × 21 cm hardcover is the entry `pixartprinting-photobook-hardcover`: single pages with 3 mm bleed on every edge, first interior page on the right, a 207 × 220 mm board, 11 mm hinges, 19 mm wrap and the spine from the quote, one PDF. A 10-page synthetic book exported with the base commit and with the catalog entry gives the same page count, the same media, trim and bleed boxes on every page and pixel-identical renders, cover included.

### Color output

`PrintSettings.colorOutput` (`ColorOutput.swift`) is optional: nil or `srgb` is the 0.10 behavior, and the viewing PDF and the editor are always sRGB. `cmyk` names an `ICCProfileReference`: a stable id of the source (`eci:PSOcoated_v3`, `installed:<file>`, `file:<file>`, `bundled:<file>`), the profile's own description, and the copy in the package's `profiles/` folder with its SHA-256, so the book carries the profile it prints with. `BookStorage.importICCProfile` accepts only an ICC file whose header says output class `prtr` and data space `CMYK`, and never renames or alters the profile; `BookStorage.converter(for:in:)` refuses a copy that is missing or whose hash changed. The preflight reports either as a blocker, and a print service that asks for the other color mode as a warning.

`CMYKConverter` converts sRGB to the output profile with relative colorimetric intent and black point compensation. The spike for T12 (macOS 27, Xcode 27.2 SDK, Adobe's Coated FOGRA39 and Coated GRACoL 2006 as found on the build Mac, and the system's Generic CMYK) found:

- Drawing an sRGB image into a CMYK bitmap context ignores `setRenderingIntent` and gives the perceptual result.
- `ColorSyncTransformCreate` with the relative intent matches Little CMS 2 (ImageMagick 7.1.1, `-intent relative`) within 4/255. Its `kColorSyncBlackPointCompensation` option, on the source entry or in the options, moves paper white (2 % C and M on FOGRA39, 11 % on Generic CMYK) and the hue of neutrals and reds, unlike Little CMS's compensation; on the destination entry alone it does nothing.
- So the converter runs ColorSync sRGB → Lab (relative), applies the compensation in XYZ as Adobe and Little CMS define it (`X' = X · (W − B) / W + B`, `B` the profile's black from Lab 0 through the profile and back), then ColorSync Lab → CMYK (relative). ColorSync's float Lab is encoded as `L / 100` and `(a + 128) / 255`. The result matches Little CMS's relative colorimetric with compensation within 5/255 on white, black, dark gray, mid gray, pure red and a skin tone, for FOGRA39 and Generic CMYK.
- The conversion is computed once per profile into a 33-step table and applied to the finished photo (after adjustments, film look, grain and the bleed reflection) with `vImageMultiDimensionalInterpolatedLookupTable_Planar16Q12`, in strips of 128 rows: 45 ms for 12 MP. vImage reads the table entries as 16-bit fractions (65535 = 1) and writes 16Q12 planes. Images agree with the exact solid-color path within 3/255.
- A CMYK `CGImage` encoded as JPEG by ImageIO and loaded with `CGImage(jpegDataProviderSource:)` is embedded by Quartz as it is: `/DCTDecode`, `ICCBased` with `N 4` and `/Decode [1 0 1 0 1 0 1 0]` for the Adobe-inverted data, with no second compression; rendering the PDF back gives the bitmap within 1/255.

Every color drawn on a print page reads `PrintColor.converter`, a task-local value the exporter sets for one document: `EditorialStyle.color` (text, captions, rules, borders, marks) gives black ink only for a near-gray (`0 0 0 K`, see below) and the profile's CMYK otherwise; `EditorialStyle.fillColor` (paper, panels, box fills, cover backgrounds) always goes through the profile, so a dark page is not flat black ink; photographs are converted before JPEG encoding. Colors are created in the profile's own `CGColorSpace`, the same one the output intent embeds, so black ink stays black ink at the printer. The output intent names the profile by its description and embeds it; the file is not labelled PDF/X (decision D6).

When a print service sets `color.flattenTransparency`, `PrintColor.flattensTransparency` is on: each translucent story panel, and the classic cover band, is rendered in sRGB at the print resolution with the paper and the photos beneath it, converted, and placed as one opaque image; the text is drawn on top as text. Without it the PDF keeps the live transparency of 0.10.

PSO Coated v3 may not be distributed (decision D7). `ECIProfile.install` fetches ECI's archive (`https://www.eci.org/lib/exe/pso-coated_v3.zip`, confirmed on ECI's downloads page on 26 November 2026, 1.7 MB) only on the author's click, extracts it with the system's `ditto` into a temporary folder, runs nothing from it, checks that the file is a CMYK output profile named PSO Coated v3 with an intact MD5 profile ID, and keeps it in `~/Library/Application Support/PaperAndGrain/Profiles`. A failed download or check leaves nothing behind. ECI publishes no checksum; `ECIProfile.expectedSHA256` was read from a download on 26 November 2026 and the check compares it and the exact description. The archive is streamed to disk with an 8 MB limit, links and non-regular files in it are refused, and the profile may not exceed 6 MB. `ICCProfileSources.bundled` lists GRACoL2006_Coated1v2 and Coated_Fogra39L_VIGC_300 from the ICC registry in `Resources/ICCProfiles` with their SHA-256 (terms in its `CREDITS.md`). `ICCProfileSources.installed` lists, through `ColorSyncIterateInstalledProfilesWithOptions` (waiting for the cache), the CMYK output profiles on the Mac. `ICCProfileSources.candidate(for:)` maps the profile a print service names (`FOGRA39`, `Coated GRACoL 2006`…) to a press-condition family and returns the bundled, ECI or installed profile of that family; **Book & Print** names it and chooses it when CMYK has no profile yet. A profile chosen in **Book & Print** is copied into the package only on **Apply**.

Text, rules and borders use black ink only when their Lab chroma C* is at most 7 (`CMYKConverter.neutralChroma`): every template's ink, caption ink and caption ink over photos is a warm or cool dark gray up to C* 6.8, while a visibly tinted color keeps its four inks. K is matched to the color's L* after black point compensation. When transparency is flattened, the image under a story panel also holds the text boxes and captions below the panel. `ICCProfileSources.installed` lists the CMYK output profiles ColorSync finds on the Mac.

### Soft proof and gamut warning

`CMYKConverter` keeps a second 33-step table, sRGB → CMYK (the print conversion, black point compensation included) → sRGB (ColorSync, relative colorimetric), so the paper shows as the screen's white; the proof shows the gamut change and also the shadows that black point compensation lifts. **View › Proof Colors** (`EditorView.proofColors`, a view state, never saved) is available when the book writes CMYK and the Issues list does not report its profile as unusable; turning it on reads and hashes the profile off the main thread, and it turns off when the book goes back to sRGB. Canvas preview requests carry `EditorPreviewRequest.proof` (the profile reference and the package), so proofed previews have their own cache entries; the loader builds or reuses the converter inside the render and returns nothing if the profile cannot be used, so an sRGB image is never cached under a proof key. Thumbnails, film swatches, the Compare sheet and the PDF never proof. The canvas shows a **Proof:** tag with the profile's description.

`CMYKConverter.outOfGamutShare` measures the share of an image whose proof lies more than 8 in a*b* (`gamutChromaLimit`) from the original after black point compensation: the print lowers the chroma of dark tones on purpose, so navy shadows and dark reds are not counted, and lightness is left out. `GamutEstimate.Request` names a photo, its look and adjustments, the part shown in its frame (normalized, rounded to 1 %) and the profile hash; it is also the cache key. The preflight only reads `GamutEstimate.cachedShare` and lists the requests it lacks in `Preflight.pendingGamut`, so the other issues publish within T1's budget. `IssueMonitor` hands them to its `GamutEstimator` actor, which renders the shown part at about 160 px (`GamutEstimate.estimate`), two photos at a time at utility priority, never adds a request twice, and calls back after every six photos and at the end; the monitor then checks the book again at once. Ordinary edits add requests and do not cancel the estimator; another profile or closing the book does. The preflight adds `outOfGamut` when the share reaches 10 % (`warningShare`). With the bundled FOGRA39 a saturated synthetic image (primaries and secondaries) is well above it; a gray ramp, skin and sky tones, a navy shadow (10, 15, 50), a dark red (70, 10, 10) and a night blue (5, 10, 35) are below. The profile file is hashed once per change on disk (`BookStorage.converter` remembers the size and date it checked).

## Film

`FilmRenderer` reads the oriented image with ImageIO, normalizes it to sRGB with ColorSync and applies the look, or a 3D CUBE or HaldCLUT PNG. A `.cube` file accepts `DOMAIN_MIN`, `DOMAIN_MAX` and `LUT_3D_INPUT_RANGE` and skips other keywords; 1D LUTs are refused with a clear message. Hald PNGs are accepted from level 2 to 12; level 12 is resampled to a 64-step cube. Strength blends the look with the scene, and grain adds a repeatable variation to the luminance. The original view in the editor is a temporary viewing mode. The document stores the book look and the per-photo overrides. The preview cache is limited and keyed on image, look details and resolution. The PDF reads the copy again at the resolution the format needs.

The book template is optional. Page color, typography, text column and gaps come from the parameters in `BookTemplate.swift`. The print safe zone sets the minimum margin. [Book templates](templates.md) describes how they are applied and previewed.

PostScript font, size in points and alignment are optional fields and inherit one by one. The book template gives the starting values. The book can override those of headings and body text. A page can add changes to its own heading or story. The front cover, the back cover and the boxes can override their text style as well. Core Text applies the resolved style on the canvas, in thumbnails and in the PDF. Rendering falls back to the template typeface when the chosen font is missing on the Mac.

## Canvas, events and previews

`CanvasDeleteShortcut` observes keyboard, clicks and scroll wheel in the window without intercepting them, except in the cases it handles. A right-click on the canvas selects the object under the pointer and shows an `NSMenu` built at that moment by `EditorView.canvasMenu(at:)`, so the items always act on that object. `PageScrollGesture` turns one page per trackpad gesture or per wheel notch and absorbs the momentum. It does so only with the **Fit Page** zoom and with no edit in progress. Arrow keys first move the selected object, then change page in the navigator or on the empty canvas. The floating controls above the page register their own frame (`EditorDropTarget.canvasHUD`, `.canvasViewControls`): a click on them does not change the selection.

Sliders do not use `Slider(step:)`. On macOS the step creates a tick mark for every value, and AppKit recomputes hundreds of rectangles per slider when the panel appears or disappears. The value is rounded in the setter (`PhotoAdjustmentsPanel.quantized`). The **Adjust** sections start collapsed. The navigator is wrapped in `Memoized`, which redraws it only when `NavigatorKey` changes: book, current page, width, insertion during a drag and comparison with the original. Actions read the live state at click time, so they are not part of the key. Any new data shown by the navigator must be added to the key.

Film has a single visible interface at a time. With a photo selected it sits in the **Photo** tab and changes `BookPhoto.film`. If **Change the whole book** is ticked, it changes `Book.film` and removes the selected photo's override in the same undoable action. With nothing selected, the **Film** tab changes `Book.film`. `filmScope` derives from the tab and the checkbox.

`BookPage.duplicated()` (`PageDuplication.swift`) backs **Page › Duplicate Page**: the copy gets a new page id and new text box ids, `layerOrder` is rewritten to the new box ids, and photo ids are kept because a photo may sit on several pages. `EditorView.duplicatePage` inserts it after the original in one `editPages` step and registers a second undo action that moves the page selection back to the original (and forward again on redo). The command is off on the covers and while text, a crop or a library search is active, which is what lets ⌘D stay free of the text field.

Dropping a photo from the photo library on a page goes through `EditorView.photoDropAction`. There are five outcomes:
- **swap**, with a photo on the same page;
- **replace** (`BookPage.replacePhoto`): the new photo takes the order position, template slot, frame and layer of the one under the pointer. In an automatic gallery the visible frames are fixed first, so the page is not laid out again;
- **empty slot** (`BookPage.fillSlot`): if the order position already matches the slot, the photo stays automatic; otherwise it gets the slot as its frame;
- **first photo** of an empty automatic page;
- **free frame**, always with **⌥**.

`PageComposition.emptySlots` treats a slot as empty when no photo covers at least half of it. The canvas placeholders and the drop both use it. Canvas objects are `focusable` but have no system focus ring (`focusEffectDisabled`): the app draws the selection itself.

`EditorPreviewLoader` runs up to four canvas previews in parallel, newest request first. `EditorPreview` asks for the size that suits the on-screen frame (480, 720, 1080, 1440 or 2048 px, taking Retina screens and the crop into account) and shows the navigator thumbnail already in memory at once, while the sharp one arrives.

## Localization

The interface is in English and Italian. Strings live in the String Catalog `Resources/Localizable.xcstrings`, with English as the source language and the English text as the key; where the same English needs different Italian, an explicit key is used. `L10n` resolves a key in the interface language chosen in **Settings** (system, Italian or English) by loading the matching `.lproj` bundle, and falls back to the key, so `swift test`, `swift run` and the CLI show English. Command-line output is not localized. Views and commands conform to `Localizing` (`tr("Page")`, `tr("Layout", key:)`, `tr("%lld pages", n)`); counts use the catalog's plural variations with positional format arguments. The CLI calls `L10n.useEnglishOnly()`; its `templates` output takes Italian names from a small table that a test keeps equal to the catalog. Preflight results are `PreflightIssue` values (a location and a problem) localized when shown, so the export sheet is in the interface language and `export-pdf` reports English. `scripts/l10n-pairs.py check` guards against inline strings, missing keys and unused keys. `Resources/it.lproj/InfoPlist.strings` holds the Italian Photos permission text.
